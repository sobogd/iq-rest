# iq-rest-public-menu

Vite + React 19 single-page app — the IQ Rest **public menu** (guest-facing). When a diner scans a table QR code at a venue, the QR opens this app at `<slug>.iq-rest.com` (optionally `?table=N`); the diner browses the menu, places an order, and/or books a table. The backend is `iq-rest-public-menu-api`; the data shown here comes from a single restaurant-by-slug fetch.

> **Schema cleanup 2026-05-28 (Stage C).** `RestaurantPayload` (in `src/lib/types.ts`) no longer carries a nested `company` object — `plan`, `subscriptionStatus`, `trialEndsAt` are flat on the restaurant. The trial-overlay gate in `src/routes/__root.tsx` reads them directly. See `/home/deploy/dev/AUDIT_2026-05-29.md` for the audit (notably: null `trialEndsAt` on a non-paid plan currently fails OPEN; client-supplied order `total` is trusted by backend; missing focus traps on modals; eagerly bundled locale JSONs).

## Build rule on this server (read first)

This server has ~3.7 GB RAM. **DO NOT run production builds here**:

- Forbidden: `npm run build` (which runs `tsr generate && tsc -b && vite build`) and `npm run preview`.
- Allowed for type checks: `npm run typecheck` (which runs `tsr generate && tsc -b`) or `npx tsc --noEmit`.
- Allowed: `npm run dev` (Vite dev server on `:8132`).
- All production builds happen in GitHub Actions on push.

## Where it fits in IQ Rest

```
guest phone (scan QR on table)
        |
        v
<slug>.iq-rest.com  ──> this app  ──HTTP──> iq-rest-public-menu-api  ──pg NOTIFY──> iq-rest-dashboard-api  ──SSE──> dashboard + tablets
                                                                                                                       (KDS / waiter / reservations)
```

A guest never authenticates. The restaurant slug is the only state in the URL; `?table=N` (from the per-table QR) and `?preview=1` (used by the dashboard's "Preview" button) are forwarded across every navigation.

## Tech stack

- **Vite 6** + React 19 + TypeScript 5.7
- **@tanstack/react-router 1.95** (file-based routes — `tsr generate` writes `routeTree.gen.ts`)
- **@tanstack/react-query 5** (single `QueryClient` in `main.tsx`; `staleTime: 30s` default)
- **i18next 24** + `react-i18next 15` + `i18next-browser-languagedetector` — 35 locales auto-loaded
- **Tailwind CSS 3.4** + autoprefixer + postcss
- **lucide-react** (icons)
- **@googlemaps/js-api-loader** (lazy-loaded for contacts map)
- **date-fns 4** (reserve form calendar)

No router CSR auth, no axios — plain `fetch("/api/...")`. Dev server proxies `/api` to `VITE_DEV_API_PROXY` (default `http://localhost:8131`).

## URL structure

- **Restaurant**: `<slug>.iq-rest.com` → `resolveSlug()` strips `.iq-rest.com` and returns the subdomain. For local dev, pass `?slug=<name>`. `www` is ignored.
- **Table-bound order**: any URL may carry `?table=N`. `OrderForm` reads it via `getTableNumber()`, displays the badge "Table N", and sends `tableNumber` to the API.
- **Dashboard preview**: `?preview=1` disables analytics tracking. `MenuNavLink` and `useForwardedSearch()` ensure both params survive every internal navigation.
- **Forced locale**: `?lang=<code>` overrides the restaurant's default language at boot, but only when that locale is in `restaurant.languages`. Used by the landing's demo iframe.

## Routing

File-based via `@tanstack/router-plugin/vite`. TanStack dot-separated filenames create nested children — `menu.group.$id.tsx` is `/menu/group/$id` and renders as a child of `/menu` (`menu.lazy.tsx` outputs `<Outlet />` when the URL is not exactly `/menu`).

| Route | File | Component | Notes |
|---|---|---|---|
| `/` | `routes/index.tsx` | `HomePage` | Hero (image/video/colour), nav links (`/reserve`, `/contacts`, `/language`, `/menu`). Reserve link hidden unless `reservationsEnabled`. Language link hidden if ≤1 language. Emits `Restaurant` JSON-LD. |
| `/menu` | `routes/menu.tsx` + `menu.lazy.tsx` | `MenuPage` → `MenuIndex` | Index of groups + leaf categories. Layout `flat` (horizontal tabs + feed) or `drill` (vertical list → screen). Skips empty groups and categories with no items. Diet filter button + sheet when any top-level dish has a diet tag. Emits `Menu` + `MenuItem` JSON-LD. |
| `/menu/group/$id` | `routes/menu.group.$id.tsx` | drills into a group's child categories |
| `/menu/cat/$id` | `routes/menu.cat.$id.tsx` | renders a single category's dishes (drill leaf) |
| `/reserve` | `routes/reserve.tsx` + `reserve.lazy.tsx` | `ReserveForm` | Week picker (60-day window), slot fetch from `/api/public/reservations/availability`, table picker (capacity ≥ guests), POST to `/api/public/reservations`. Honors `reservationSchedule` (closed days dimmed). |
| `/contacts` | `routes/contacts.tsx` + `contacts.lazy.tsx` | Phone / Instagram / WhatsApp / address / Google map (loader from `lib/maps-preload.ts`). |
| `/language` | `routes/language.tsx` + `language.lazy.tsx` | Language switcher (`restaurant.languages`). |
| `/order` | `routes/order.index.tsx` + `order.index.lazy.tsx` | `OrderForm` — cart, required-field validation, WhatsApp + Internal modes, table-bound. |
| `/order/success` | `routes/order.success.tsx` + `order.success.lazy.tsx` | Post-submit confirmation. |

`__root.tsx` warms `["/menu", "/menu/group/$id", "/menu/cat/$id", "/reserve", "/contacts", "/order", "/order/success", "/language"]` via `router.preloadRoute({ to })` on mount and lazily preloads Google Maps via `requestIdleCallback` so navigation never blocks on a network fetch.

## State management

- **Restaurant snapshot** — a single React-Query call (`["menu", slug]`) in `__root.tsx` with `staleTime: Infinity` and `retry: 3`. The result is passed through `<MenuProvider menu={data}>` and read everywhere via `useMenu()`. There's no other server-state fetch — every other screen renders off this single snapshot, except `ReserveForm` which fetches availability per-date.
- **Cart** — `useCart()` (`lib/cart.ts`). Persisted to `localStorage` under key `iqr_cart` as `{ [itemId]: qty }`. Cross-tab sync via the `storage` event. No server-side cart.
- **i18n** — `i18next` instance in `lib/i18n.ts`. Resources are loaded eagerly via `import.meta.glob("../locales/*.json", { eager: true })`. Initial language is `en`; `__root.tsx` switches to the URL's `?lang=` (if enabled) or the restaurant's `defaultLanguage` once the snapshot arrives. `tField(value, translations, "name", lang)` is the helper used everywhere to resolve a translated string with fallback.
- **Per-route URL params** — `useForwardedSearch()` always returns `{ table?, preview? }` from `window.location.search`. Pass it into every `navigate({ to, search })`. `MenuNavLink` wraps `<Link>` and does this automatically.

## Theming and branding (per restaurant)

All applied inline via `restaurant.accentColor`:
- Home: hero (`source` image or video, or solid colour fallback), centred big title (unless `hideTitle`), accent-coloured "Online menu" CTA.
- `MenuHeader`, primary buttons, count badges, focused input borders.
- `menuLayout`: `"flat"` (horizontal tabs + dish feed) or `"drill"` (vertical list → screen). Groups, when present, always show as a drill above the layout.

## Order submission (`components/order-form.tsx`)

1. Builds **expanded items** — one row per unit (so `qty: 3` → 3 rows) with both legacy flat fields (`name`, `qty`, `price`) and rich fields the new dashboard expects (`id`, `dishId`, `dishNameSnapshot: Record<lang, string>`, `basePriceSnapshot`, `options: []`, `notes`, `status: "pending"`, `createdAt`).
2. Owner-facing label uses `restaurant.defaultLanguage` (so staff see the order in their working language even if the diner browsed in another locale). Visitor-facing label uses the diner's current i18next language.
3. `POST /api/public/orders { slug, items, total, customerName, customerPhone, customerAddress, comment, tableNumber }`. Backend echoes `{ ok, mode }`.
4. On `mode === "whatsapp" | "both"` opens a `https://wa.me/<digits>?text=<encoded>` deep link with a WhatsApp-formatted summary (table, items, totals, contact fields). Then `clear()` cart and `navigate("/order/success")`.

Required-field validation reads `restaurant.{orderNameEnabled, orderPhoneEnabled, orderAddressEnabled}`.

## Reservation booking (`components/reserve-form.tsx`)

1. Week picker showing 7 days at a time, up to 60 days ahead. Days marked `closed: true` in `reservationSchedule[(getDay+6)%7]` are dimmed.
2. After guests + date are picked, fetches `GET /api/public/reservations/availability?slug=&date=&guests=` → `{ timeSlots, slotDuration }`.
3. After picking a time, fetches the same endpoint with `&time=HH:MM` → `{ tables }` and renders only suitable tables (capacity ≥ guests). Translated zone via `getTranslatedZone(table, locale)`.
4. `POST /api/public/reservations { restaurantId, tableId, date, startTime, guestName, guestEmail, guestPhone, guestsCount, notes, locale }`.
5. Status flips to confirmed if `reservationMode === "auto"`, else pending — confirmation comes via email (sent server-side by public-menu-api).

## Analytics (`components/menu-page-tracker.tsx`)

Posts `/api/analytics/track` on every `location.pathname` change with `{ slug, page, language, referrer }`. Skips visits with `?preview=1`. Uses `credentials: "include"` so the `sqr_session_id` cookie is sent.

## SEO

`route-seo.tsx` writes `<title>` and meta description per page, plus injects `application/ld+json` blobs:
- `/` — `Restaurant` schema (name, address, telephone, geo if x/y, image if source is non-video).
- `/menu` — `Menu` + `hasMenuSection` (one per non-group category) + `hasMenuItem` (with `price` + `priceCurrency`).

## Trial overlay

Shown when `restaurant.company.plan === "FREE"` AND `trialEndsAt` is in the past, except for the demo restaurant `love-eatery` (used in the landing's iframe demo). Renders on top of `<Outlet />`; the rest of the app still mounts so analytics + SEO continue to fire.

## Bootloader

`index.html` ships an inline black-background spinner (`#boot`). `__root.tsx` removes it via `document.getElementById("boot")?.remove()` once the menu fetch settles (success or error). While `isLoading` is true after that, the layout still renders a black div with the same look, so the visual state stays single across mount → fetch → first paint.

## Conventions

- **No server-state proliferation** — one menu snapshot per session; everything else reads `useMenu()`. Don't add ad-hoc `useQuery` calls for data already in the snapshot.
- **Forward search params** — every `navigate(...)` / `<Link>` must preserve `?table` and `?preview`. Use `MenuNavLink` or `useForwardedSearch()`.
- **Inline-style accent colour** — Tailwind handles layout; per-restaurant accent is applied via `style={{ backgroundColor / color / borderColor }}`. Don't try to wire dynamic Tailwind class names.
- **localStorage only for the cart** — no other client persistence.
- **Manual chunking** in `vite.config.ts` keeps `vendor` (react + router + query) and `i18n` (i18next + react-i18next) in their own chunks for cache reuse.
