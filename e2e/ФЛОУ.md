# E2E — единый happy-path (локальный dev-стек)

Один сквозной happy-path через **реальный UI**: от логина на лендинге до
публичного меню в **мобильной** версии. Гоняется против **локального dev-стека**
(`./scripts/dev.sh`) и **локальной БД**. Реальный бэкенд, реальный Gemini.
Никакого Docker.

---

## Запуск

```bash
cd iq-rest && ./scripts/dev.sh      # поднять стек (порты 8001-8005), если ещё не поднят
npm run e2e                          # из корня монорепы  (или: cd e2e && npm test)
```

Первый раз: `npm run e2e:setup` (ставит deps e2e + Chromium для Playwright).
Стек должен быть поднят — иначе global-setup упадёт с подсказкой.

**Каждый прогон:** global-setup чистит остатки прошлых прогонов → тест создаёт
ОДИН свежий ресторан → после прогона **global-teardown удаляет этот ресторан и
всё связанное** (столы, заказы, брони, категории, блюда, устройства, аналитика)
+ автотест-юзера. Трогаются ТОЛЬКО аккаунты на `@e2e.iqrest.test`.

---

## Локальный стек

`./scripts/dev.sh` (pm2), локальный Postgres `localhost:5432/iq_rest`.

| Сервис | Порт | Заметки |
|---|---|---|
| landing | 8001 | точка входа — логин |
| dashboard-web | 8002 | baseURL Playwright |
| dashboard-api | 8003 | `NODE_ENV=development` → OTP-байпас + пропуск писем |
| public-menu-api | 8004 | |
| public-menu | 8005 | мобильный флоу публичного меню |

Playwright резолвит `E2E_DATABASE_URL` из `apps/dashboard-api/.env` (DATABASE_URL),
порты — из дефолтов конфига (`playwright.config.ts`). Всё переопределяется env.

## Заглушка авторизации

`auth.service.ts`: для email на домене `@e2e.iqrest.test`, **только вне
продакшена**, OTP форсится в `000000`, письмо не шлётся. Happy-path берёт
уникальный `happy+<время>@e2e.iqrest.test` на прогон (send-otp лимитируется по
email).

## Сам happy-path (`tests/happy-path.spec.ts`)

Каждый шаг в файле помечен нумерованными комментариями (1. открыл, 2. кликнул…).
Хелперы сборки меню/столов/заказов — в `tests/helpers.ts`.

1. **Логин с лендинга** — auth-модалка → email → OTP `000000` → дашборд.
2. **Онбординг с чистого листа** — Skip у имени, «Start from scratch»
   (ресторан с ОДНИМ языком, пустое меню; orders выкл, bookings вкл, триал=PRO).
3. **2-й язык в настройках** — ДО первой категории: включить «Español» → сохранить.
4. **Богатое меню** — 2 группы, 3 категории, 3 блюда. Блюдо `Carbonara` создаётся
   СРАЗУ с описанием (комментарий гостю) + ОБЯЗАТЕЛЬНОЙ опцией `Size` (single) +
   ОПЦИОНАЛЬНОЙ `Extras` — через реальные формы опций/вариантов.
5. **Автоперевод** — es-поле имени блюда заполнено автопереводом.
6. **Валидации формы блюда** — пустое имя → модалка; пустая цена → модалка;
   санитайз цены (`1.2.3`→`1.23`, `3,50`→`3.50`, буквы срезаются).
7. **Форма опции** — на `Margherita` добавить МНОЖЕСТВЕННУЮ опцию `Sauces`: тоггл
   multi; пустое имя варианта → модалка; priceDelta с запятой; es-перевод;
   удаление варианта.
8. **Столы** — 2 стола разного размера/формы/цвета/зоны через формы (степперы
   мест, выбор формы, свотч цвета) + перетаскивание маркеров по floor-map, чтобы
   не накладывались.
9. **Настройки заказов** — включить «Accept orders», сохранить.
10. **Заказы (весь раздел)** — создать заказ на столе; добавить `Carbonara`
    (size=Large, extra Bacon ×2, коммент) + `Margherita` + `Cola`; проверить,
    что опции и комменты вывелись на строках; сменить стол; скидка на заказ (10%)
    и на позицию (fixed); дублировать блюдо; редактировать блюдо; разделить заказ;
    закрыть заказ с оплатой (Cash); удалить оставшийся заказ.
11. **Настройки бронирований** — прогнать тоггл enable (в итоге вкл), сохранить
    (режим по умолчанию Manual → брони приходят как pending).
12. **Публичное меню — брони** — гость через форму `/reserve` создаёт 2 брони
    (гости → дата → слот → стол → контакты → отправка → экран успеха).
13. **Бронирования в дашборде** — 2 pending; подтвердить одну, отклонить другую.
14. **Публичное меню (МОБИЛЬНОЕ)** — мобильный viewport, открыть меню, сменить
    язык на «Español» **кликом по UI**.

## Нюансы

- Публичное меню локально требует `?slug=` (в проде slug = сабдомен). Внутренние
  `<Link>` его роняют → страницу языков открываем со `slug`, а сам **язык меняем
  кликом по «Español»** (это и есть UI-смена языка).
- Смена языка не персистится в localStorage → флоу держится в рамках одного
  прохода без перезагрузки, теряющей язык.
- `retries=0`: happy-path — одна длинная история; ретрай переиспользовал бы
  грязное состояние БД. global-setup чистит автотест-аккаунты в начале, а
  global-teardown — в конце (удаляет созданный ресторан со всем связанным).
- Уборка БЕЗОПАСНА: `purgeAutotestData` (в `provision.ts`) трогает только
  рестораны, чей владелец на `@e2e.iqrest.test`. Удаляет каждую таблицу с
  колонкой `restaurantId` (аналитика без FK не каскадит) + сам ресторан
  (каскадит столы/заказы/брони/категории/блюда/устройства) + автотест-юзера.
- Стек и БД — ЛОКАЛЬНЫЕ (`./scripts/dev.sh`, `localhost:5432/iq_rest`). Твоя dev-БД
  используется напрямую, но чужие данные не трогаются (фильтр по тест-домену).
- Письма на `@e2e.iqrest.test` вне прода НЕ шлются (guard в обоих mail.service) —
  никаких отбивок от тестовых броней.
